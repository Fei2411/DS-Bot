# PR 界面检查清单（一页）

配合 [UI 设计标准](ui-standard.md) 的逐 PR 检查表。对着 PR 的界面改动逐条打勾，**结论复制到 PR 评论**。任一条落在「硬门槛」里即退回，不看其他分项。

标准里的条款用「§」引用；本页只列检查动作，不重复条款全文。

## 硬门槛（命中即退回）

- [ ] 正文/数据文字对比度 ≥ 4.5:1，图标/边框 ≥ 3:1（明暗两套各测一次，写明数值；§2.6）
- [ ] 380px 宽下无横向裁切、无文字被切半个字（`scrollWidth <= clientWidth`，且每个元素右缘不越界；§4.5）
- [ ] 图标按钮都有 `aria-label`；状态类控件有 `aria-pressed` / `aria-selected` / `aria-expanded`（§12）
- [ ] 没有新增类名冲突（新类名在 `styles.js` 里搜不到第二个组件在用；§10.0）
- [ ] 展开区的内容不在触发按钮内部（读屏不能把内容读成按钮名；§12）
- [ ] 破坏性操作与常用操作间距 ≥ 16px，破坏性操作在最右（§10.13）

## 1. 尺寸与档位

- [ ] 字号只取 §3.2 档位（11/12/13/14/15/17/22/34）；新增字号要写理由
- [ ] 行高、圆角、控件高度都落在表内（§4.2、§5）
- [ ] 可点区域：桌面 ≥ 28×28，窄窗/触屏 ≥ 44×44（§4.2）
- [ ] 换行、省略号在窄窗下不产生跳动（同长度内容前后对比）

## 2. 颜色与对比度

- [ ] 只用 `--bt-*` 变量，没有写死色值（§2.2）
- [ ] `--bt-ink-3`（36%）没有承载任何要读的信息（时间/计数/状态/原因都不行；§2.6）
- [ ] 语义色作为文字时，在它实际底色上单独验过；浅底徽标用深字，不是同名色字（§2.6、§10.15）
- [ ] 深色主题单独截一张

## 3. 布局与断点

- [ ] 1440 / 1024 / 760 / 640 / 480 / 380 六档各截一张（至少 1440 / 760 / 380 三档；§4.5）
- [ ] 头部、行内操作、状态列在 640 以下按 §4.5 变形，按钮不各占一整行
- [ ] 新加的固定宽控件写明了它开始裁切的窗口宽度

## 4. 数字与文案

- [ ] 数字列右对齐 + `tabular-nums`；单位写在表头（§3.3）
- [ ] 0 与空值可区分（`0` / `—`；§3.3）
- [ ] 多个时间点按先后排、标签只出现一次（§3.3）
- [ ] 文案走 `t()`，英文写源文、中文进 `i18n.js`（§11）
- [ ] 同一组里的标签同语种、同类词（不要 `全部 / Bot / 群聊`；§10.11）
- [ ] 不写过程、不写计划、不写「稍后」「下个版本」（§11）

## 5. 键盘与读屏

- [ ] Tab 顺序与视觉顺序一致，每个可交互元素都能到（§12）
- [ ] Esc 关闭最上层；菜单支持方向键（§12）
- [ ] 焦点环可见，且同一类控件只用一种写法（§12）
- [ ] 动态状态（进行中 / 已暂停 / 已停止）有 `aria-live` 播报（§10.15、§12）
- [ ] 二次确认、错误提示都有文字，不只靠颜色（§12）

## 6. 截图与证据

- [ ] 前后对比各一张，同一窗口尺寸、同一份数据
- [ ] 数据脱敏（不用真实客户名、订单号、邮箱）
- [ ] 写了复现命令（分支、bench 名、端口、种子数据）
- [ ] 只做了浅色就写明「深色未测」，不要默认通过
