# 静默监视、完成通知和删除确认

- 日期：2026-10-30
- 来源：本次用户确认的实施方案。

## 静默监视

普通自动化继续向原会话投递。监视任务使用独立 root Session，所有权、模型、权限、能力与工作目录归属于所选 Bot。定时触发仍由 DSH schedule 服务负责，不修改 DSH。Host 必须运行，应用完全退出后不继续检查。

`create_automation` 允许 Bot 创建普通任务或监视任务。`report_monitor` 仅接受当前监视回合的结构化报告：`no_change`、`match`、`failed`。每项包含来源提供的稳定 id、正文和是否满足条件。第一次成功读取只建立基线；之后仅发布未见过的匹配 id。已见 id 持久化且不自动淘汰，失败不推进基线。

自由文本、推理、工具调用留在监视 Session，主聊天只显示插件保存的命中卡片，不额外调用模型改写。运行记录可查询原始事件，密钥经现有脱敏器处理。单次检查默认最多 5 分钟，同一 Session 串行工作，开始检查时合并积压的定时触发。没有结构化报告、取消或超时均记录为失败。

旧任务默认仍是普通任务。显式转换时创建监视任务并移除原任务；间隔任务重新计时。群任务本轮保持普通任务，用户可选择群成员 Bot 建立监视。

## 完成通知

每个 Bot 的 `notifyCompletion` 默认开启，仅用户可以修改。成功的用户任务、普通自动化结果和监视命中形成持久化完成事件。没有新消息、内部 Bot 请求、初始化、换段不产生完成通知。交办任务尚未返回或存在问题卡片、交互视图、审批时不算完成；完成的含义是运行状态完成，不判断结果质量。

桌面应用由 Host IPC 驱动 Electron 主进程通知，不依赖渲染窗口继续存在。DSH Desktop 和 Web 采用浏览器通知，在用户主动点击时请求授权。正在聚焦对应聊天不弹；通知正文不包含任务内容。通知点击回到对应 Bot，浏览器窗口通过服务端领取避免多窗口重复通知。保留最近 500 条完成事件，重连不重放旧通知。

浏览器授权、系统勿扰、macOS 签名及 Linux 通知服务可能阻止通知。Web 页面关闭后不提供推送。已有审批通知保持原规则。

## 注意力通知（2026-10-30 补充）

完成通知只覆盖"办完了"。五类"需要用户"的事件走同一 Host IPC 通道（`ds-bot:attention`）补齐桌面应用的原生提醒：审批等待（`approval/request` 挂起时）、问题卡（`ask_user`）、交互视图（`show_view`）、密钥卡（`request_secret`）、回合失败（用户或定时任务发起的回合以 error 结束）。卡片在隐藏的 Bot 互访回合里交给另一个 Bot 作答，不提醒用户。通知正文只说明事件种类（如 Waiting for your approval），不含任务内容；点击回到 Bot 所在聊天（群审批回群）。通知不持久化、不受 `notifyCompletion` 约束——该开关只管完成；不重复提醒同一 id。

回合失败的判定看回合本身是否由用户或定时器发起（turn 级标记），不依赖跨回合的待完成状态；内部 Bot 请求的失败保持安静。密钥卡等待与问题卡、视图、审批一样，阻止该回合的完成通知。

## 删除和文件

所有 UI 删除入口统一进入影响预览。原 `delete-bot` 请求拒绝无确认删除；客户端先调用 `delete-preview`，再提交短期 token 到 `delete-confirm`。后台重新核对任务、文件、会话和群关系，过期或发生变化则要求刷新。Main Bot 仍需先取消其 Main Bot 身份。

默认删除关联任务，也可选择其他 Bot 接手活动任务。普通任务通过公开 schedule 接口先建后删，间隔任务从转交时重新计时。监视任务同样重建独立 Session，复制基线、去重状态和运行记录，原 Session 归档；旧检查上下文与密钥授权不转交。正在运行的监视需先停止；转交结果不确定时禁止自动再建，界面保留进度供核对。原任务的配置与调度回执在删除进度中保留。

聊天、记忆沿用归档策略；浏览器沿用清理策略；共享密钥只解除关联。文件默认保留。仅记录明确文件工具调用前不存在、成功后出现的新普通文件，排除链接、大于 64 MiB 的文件、数据目录、已变化和已知共享文件。shell 产物和历史文件不猜测归属，不能据此批量删除工作目录。

勾选文件移入应用数据下的 `recycle/`，进度保存原路径和内容摘要。跨文件系统先复制核验再移除原文件。删除完成弹窗提供恢复入口，恢复禁止覆盖同名文件；中途失败保留逐项进度，不声称全部完成。
