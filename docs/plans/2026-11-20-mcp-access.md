# MCP 访问：让本机的其他智能体调用 DS Bot

- 日期：2026-11-20
- 相关：#494（双向 Gateway 提案）、#1294（可编程派活）

## 为什么

用户在 Claude Desktop、Cursor、Codex 或自己的脚本里工作时，想把事情交给 DS Bot 团队，或者问一句 Main Bot，现在只能手动在两边复制粘贴。DS Bot 自己暴露一个 MCP 服务器，这些智能体就能直接调用。

取舍：外部智能体按「用户授权的一个渠道」接入，和 IM、手机 App 一样，而不是当成团队成员。它代表用户说话，但拿不到用户在电脑前才有的权力（审批、回答提问、改设置、读密钥）。这样 MVP 不用碰角色与权限的设计，也不会把 Bot 内部工具或连接器转手给外部。

## 已定的行为

- **默认关闭。** 设置 → 连接 → MCP 访问里打开。只有持有团队锁的那个 dsh 提供服务；只读实例不监听。
- **只监听本机。** `http://127.0.0.1:<端口>/mcp`，默认端口 8797，可改（1024–65535）。Streamable HTTP，只用 POST + JSON 应答，不建 MCP 会话。带 `Origin` 头的请求（网页）和 Host 不是本机的请求（DNS rebinding）一律 403。
- **每个客户端一个令牌。** 在设置里按名字生成，令牌只在生成时显示一次，`mcp.json`（0600）只存 SHA-256。删除客户端立即失效。
- **按客户端限定范围。** 新客户端默认只能找 Main Bot，群聊默认没有；用户可以勾选其他 Bot 和群。隐私 Bot 永远不在范围内，也不出现在群成员列表里；勾选的群里有隐私 Bot 时，它的发言和审批不会返回给客户端。
- **七个工具，别的没有：** `list_bots`、`list_groups`、`send_to_bot`、`send_to_group`、`wait_for_reply`、`read_chat`、`list_waiting`（只读）。
- **标明来源。** 发出的消息以 `[Sent by the external agent "<名字>" through DS Bot MCP access]` 开头，请求 id 为 `mcp:<客户端 id>:<uuid>`。Bot 把它当作用户经过一个渠道说的话；来源标记只是信息，不是授权依据，高风险操作照常要人在电脑前审批。
- **长任务用轮询。** `send_*` 立刻返回 `after`（发送时间）；`wait_for_reply` 最多等 50 秒（多数 MCP 客户端约 60 秒超时），返回 `after` 之后 Bot 说的话和 `done`；没完成就带着新的 `after` 再调。
- **stdio 桥。** 只会启动命令的客户端用 `DSBOT_MCP_TOKEN=<令牌> npx -p ds-bot ds-bot-mcp [--url …]`，复用本地智能体的 stdio 转发。
- **手机和浏览器远程不能管理 MCP 访问**（`mcp-*` 端点只在电脑上可用）。

## 不做什么

- 不暴露审批、回答 `ask_user`、改权限预设、建删改 Bot、读密钥、调度任务等任何管理操作。
- 不转发 Bot 自己的 MCP 服务器、连接器或 DSH 工具。
- 不对局域网或公网开放；远程场景走手机链路。
- 不把外部智能体接入为团队里的 Bot（那是 #494 的 Gateway 方向）。

## 已知限制

- `wait_for_reply` 按消息时间和 Bot 是否在忙判断完成；同一时间用户也在和这个 Bot 说话时，返回里会混进对用户的回复。
- 只传文字，不传图片和文件。
- 令牌是持有即可用的 Bearer 令牌：本机能读到它的程序都能用它，丢了就删客户端重建。
- 客户端的消息会让目标 Bot 按它自己的权限预设跑一轮正常的回合，来源标记只是提示。所以令牌能让它的 Bot 做任何不需要审批就能做的事；默认范围是权限最大的 Main Bot，例如它的预设自动放行的创建、修改 Bot 或运行命令。删除 Bot 仍是用户操作。只把令牌给你信任的程序，或者只勾选权限更小的 Bot。
