# 统一审批代审

关联：#1299。第一版在现有 approval/request 上增加可选模型审核。

## 用户设置

团队设置的审批模型复用已配置的模型 API，默认跟随团队默认模型，允许单独指定。Bot 私聊与每个群各有独立的「替我审批」开关，默认关闭；这些设置由用户修改。审核上下文独立，审核器没有工具。

## 执行

开启后通过 DSH 的 ApprovalService.setPolicy 使用 ask，保留沙箱模式；关闭时恢复此前审批策略，用户改过权限预设时以新预设为准。新会话和子会话继续按所属 Bot 或群应用策略。所有已进入 approval/request 的请求共用审核器，正式 guard 继续执行。

捕获 tools/pre-execute 的执行参数；插件自有请求用异步局部上下文绑定当前动作证据，区分同一脚本内的多次审批。审核读取所属私聊的近期事件或群的近期完整消息，区分直接用户消息和 Bot 转述。缺少用户原话、完整动作、模型配置，或输入超过审核预算时转人工。模型返回 allow、reject 或 manual；只有严格解析并完整结束的 allow 才允许当前一次。外部 CLI 只选择显式单次允许选项。

模型调用限时 30 秒。用户取消、手动回答、停用或更换配置后，迟到的模型答复失效。审核期间上下文变化也转人工。私聊保留宿主人工卡；群和子会话由 DS Bot 展示可操作的卡。最近 100 条审核结论、模型和脱敏理由保存在团队状态，界面按私聊或群筛选最近 20 条。

## 覆盖边界

本版处理已有的沙箱提权、目录授权、浏览器敏感动作、隐私外发及外部 Agent 权限请求。浏览器表单与文件动作带具体证据；无法描述完整效果、含受保护字段或模糊删除目标时交给人工。已有站点授权照常生效，支付及其他硬拒绝照常阻止。

本版保持已有触发规则。普通权限内的危险命令、PTC 直接 Node 副作用、MCP 副作用检测，以及邮件卡和电脑应用准入迁入统一审批链，是后续独立工作。外部 CLI 自己不产生的权限请求也不会被凭空补出。问答与用户接管保持各自流程。

## 检查

覆盖严格 JSON、完整动作证据、单次批准、拒绝、人工回退、取消与迟到结果、配置变化、用户新限制、群消息来源、子会话归属及权限恢复。使用隔离 mock 环境运行仓库 smoke；真实模型判断质量与各外部 CLI 的实际权限提示行为不以 mock 结果代替。
