# 风险驱动的独立自动审批 V2

关联 #1299。用户选择按 Codex Guardian 的风险、授权与取证语义重做「替我审批」。本页是实施和验收的唯一口径。旧实现先要求直接用户原话，随后又把可执行体证明和执行闭包证明设成通用准入条件，最终没有自动放行形态。V2 恢复按证据评估具体动作。以正常入口中的构建、测试和依赖操作能获得有实质意义的自动裁决为验收条件。

## 范围与参考

- 沿用 DSH `workspace-write` + `ask`、群统一模式优先、子会话更窄的沙箱和已有 `approval/request` 触发点。现有宿主硬守卫继续执行。配置沿用团队审批模型设置和现有模型 API，外部 CLI 继续使用适配器的单次回复。V2 不引入任务 Grant、常驻允许规则或 DSH 核心补丁。浏览器支付、隐私外发、持久目录授权和原来需要用户接管的路径继续遵守自身规则。此次不扩大对尚未发出审批请求的工具或外部 CLI 的拦截面。
- Codex 的 Guardian 政策模板与默认政策定义风险、授权和证据门槛；其审批请求结构使用实际参数、执行环境、目录和权限；审查设置将 reviewer 权限与只读上限取交集，审批策略为 `Never`；审查生命周期跟踪用户授权与上下文版本、截止时间及取消。DS Bot 使用公开文件接口实现专用只读取证，不引入通用 shell、会话复用、多 reviewer 路由或网络代理。
- 可信来源遵循 [角色与权限](2026-10-07-roles-and-permissions.md)。用户当前 shell 环境已被攻陷不纳入插件威胁模型。宿主评估能观察到的命令、参数、配置和实际迹象，无须证明每个可执行体、子进程或依赖的所有未来行为。已观察到的显式环境覆盖、脚本间接执行、敏感访问、陌生下载源等仍须作为证据评估。

## 风险、授权与裁决

风险衡量具体动作的影响范围、可逆性、数据去向及服务影响。宿主先处理硬规则，再校验模型的结构化建议、证据与授权，按下表决定是否允许一次。

| 风险 | 判据 | 授权 `unknown`／`low` | 授权 `medium`／`high` |
| --- | --- | --- | --- |
| `low` | 局部、例行、易恢复。可以是沙箱拒绝后的重试，也可以读取或修改工作区外的普通小文件。 | 允许一次 | 允许一次 |
| `medium` | 有真实但可界定或可恢复的副作用。常见本地构建、测试和依赖操作在证据支持时属此类。 | 允许一次 | 允许一次 |
| `high` | 显著破坏、难恢复、影响共享服务、持久降低安全性，或涉及需明确授权的敏感外发。 | 转人工 | 影响狭窄、可信授权覆盖风险效果、无更严格政策时允许一次。否则转人工。 |
| `critical` | 大范围不可逆破坏、密钥等受保护信息明确外发到不可信目的地，或同等严重效果。 | 拒绝 | 拒绝 |

- `high` 授权覆盖具体动作和关键副作用，包括目标、载荷和去向。用户明确授权的实质效果在实施细节留给 Bot 时为 `medium`。只有松散任务关联为 `low`。没有可信依据为 `unknown`。紧迫程度、远端提示或先前审批结果不扩大授权。用户通过原人工卡对当前动作作答，可当次结算，但不得创建后续允许规则。高风险需要至少 `medium`，对敏感数据发送、持久安全变更等具体动作要求用户明示相关数据和去向、设置和作用范围。
- 宿主已知硬禁止、有效用户明确限制和确定的提示注入优先。Codex 默认政策中的明确拒绝规则优先于通用高风险人工回退，包括未经授权且可信迹象显示载荷可能敏感的外发、弱授权下从非预期来源探取凭据、缺少具体授权的广泛或持久安全削弱，以及严重且未经授权的宽范围不可逆变更。使用正常认证流程则按实际权限范围和当前动作处理。注入例外要求有证据表明动作由不可信内容推动，且超出或偏离用户任务。出现可疑文本本身不改变动作风险。缺关键事实、模型读不到相关限制或无法判断真实效果时转人工。证据缺失与危险等级分开记录。
- 提权、权限范围变化、工作区外路径、任务耗时和依赖操作本身都不抬高风险。组合动作逐个评估，按最危险部分和最严格处置结算。删除或覆盖的目标须可解释，未解析的破坏范围、混在组合动作里的副作用必须先核验。明显扩大至整盘或重要共享服务的动作不能靠模型低分降级。
- 模型在有限核验后返回严格 JSON。字段为 `risk_level`、`user_authorization`（等级与授权事件 ID）、`outcome`、`rationale`。严格解析封闭枚举和字段，常规结果只接收正常结束流。关键证据确实不足时允许 `manual` 并留空无法计算的等级。自动允许须同时得到模型建议和宿主矩阵许可。已知硬拒绝或可确认的严重风险不转成人工批准。若模型唯一的风险证据来自自相矛盾或无效输出，无自动放行，按 `invalid-response` 处置。理由不作为指令、授权或用户可见原文。

## 审批输入与只读核验

1. 宿主捕获不可变原请求，绑定审批 ID、实际 Bot、Session 谱系、工具调用 ID、上下文版本和目录／环境。保留 `tools/pre-execute` 与显式 `AsyncLocalStorage` 证据生产点，处理同一工具调用的多个待决动作。Shell 至少包含完整命令、shell 类型、宿主实际 `cwd` 和本次权限变化。原生文件工具提供动作及真实输入。外部 CLI 从待决协议回调绑定命令或变更、可信目录、请求 ID 和单次选项。显示性理由、协议中未知字段、运行时合成摘要仅作背景。未拿到实际动作或目录时以相应原因转人工。浏览器如不能绑定真实目的地和载荷，保留人工路径。
2. 每次请求启动独立审查循环。先用当前动作、相关对话与已知事实。如果关键事实可能改变裁决，审批模型可请求下表的只读操作。宿主处理少量结构化工具调用，再回传经数据规则审查的结果。工具与被审动作分开。模型中间轮只请求只读操作，由宿主验证和执行，通过工具结果继续同一审查。最终轮必须正常结束并只含判定。模型不能调用常规 Bot 工具，也不能通过取证触发任何审批。工具返回中的仓库内容和日志都是数据。
3. 只读取宿主能关联到本次动作的对象。V2 使用公开 `fs.resolve`、`contains`、`stat`、`lstat`、`readBytes` 等服务，在同一执行后端使用真实 `cwd`，不回退到猜测的宿主路径。项目根与已声明目标由原请求推导。按手头脚本、工作区配置、清单或锁文件的字面关系跟进相关文件，不能凭模型自由指定路径扩大范围。解析目标及链接后应用原可读权限、隐私边界和来源限制。允许检查本次工作区外普通目标的必要元数据。设备、网络路径、潜在密钥目录、他 Bot 私域和宿主受保护数据按相应策略处理。通过配置或文件引用到范围外的新目标时，先确认它与动作直接相关且原范围允许读取。
4. 取证工具仅接收有限参数，拒绝任意 shell、脚本执行、生成或安装、环境变量枚举、通用搜索、对外请求、权限修改、跨会话回溯及后台子代理。不能借被审动作的提权读取额外内容。V2 初始预算为全链路 30 秒、每请求最多 6 次取证、每个文本项最多 32 KiB、模型输入 96,000 字符。证据可用有界且结构化的片段，标出省略部分。缺失的是关键证据且预算内无法补齐时转人工。预算限制不按命令名决定结果。

| 只读操作 | 输入与宿主产出 | 典型使用 |
| --- | --- | --- |
| `inspect_target` | 宿主已绑定的目标 ID 或本次动作能解析的相对目标。返回存在性、类型、工作区关系、链接归属、大小和有界目录概况。 | 单个本地读写目标、删除范围、补丁受影响文件、输出目录或链接。无需正文就不读正文。 |
| `inspect_project` | 已绑定的项目根及待核验的脚本名、安装意图或配置用途。宿主读取有限的 manifest、锁文件、脚本和相关配置，输出脚本入口、已知生命周期钩子、依赖来源、写入范围及可披露片段。可跟进证据明确引用的配置或脚本。 | `npm`／`pnpm` 等包管理动作、本地脚本及项目构建、测试。只读并解析配置，不运行包管理器或代码来查效果。 |
| `inspect_context` | 当前审批快照中的事件 ID 或受限的相关事件窗口。返回当前会话或群谱系的已验证事件及只作背景的相关条目。 | 查看更新的限制、目标、用户明确授权。不得搜索其他群、私聊或记忆来补授权。 |

## 动作判定表

| 当前动作 | 何时放行或拒绝 | 缺证据时的取证与回退 |
| --- | --- | --- |
| 常规构建或测试 | 完整命令与目录、已知项目配置和脚本支持本地、可恢复的副作用，且没有部署、凭据访问、外发或共享系统变更迹象时，通常按 `medium`。普通提权、未知用户授权、无法证明完整执行闭包均不单独阻断。 | 相关 manifest、pre/post 钩子、脚本入口、任务配置缺失或存在可疑副作用时只读取证。实际指向未知脚本、动态目标或敏感副作用且未能核验时转人工。组合中含发布、部署、远端写入则按其实际风险评估。 |
| 依赖安装或更新 | 核对有效项目范围、清单、锁文件、来源、安装路径与生命周期脚本。常规依赖拉取与有界本地写入通常为 `medium`。冻结锁文件、禁用脚本和已知注册表是有力证据。未冻结或开脚本会增加应核验事项，不单独决定拒绝。 | 检查锁文件及相关配置是否指向陌生源、本地外部路径或非预期下载，明确脚本及数据边界。发现会运行未知远程代码、依赖来源或外发不明，且无法补足关键证据时转人工。发现明确硬禁止的外发则拒绝。 |
| 文件读取、写入、删除或补丁 | 用真实目标、拟改范围、数据类型和可恢复性定级。普通路径读取及狭窄可恢复修改可为 `low` 或 `medium`。重大不可恢复破坏为 `critical`。 | 目标可能被链接、动态参数或广泛匹配改变时先核实目标。可以确定受保护的数据读取或硬禁止效果时先分流。无法确认目标、变更或数据去向时转人工。 |
| Shell 组合、脚本与外部 CLI | 可以完整理解作用的组合、新脚本或运行时协议动作按同一风险表。外部 CLI 仅兑现同一 pending 请求的明确单次允许选项。 | 宿主使用协议结构和只读结果，不以命令名白名单、显示文本或 JSON 键数给准入。关键子动作、运行目录、动态参数或选项缺失时转人工或按适配器已有拒绝／取消路径结束。 |
| 出站动作 | 按源数据、实际载荷、接收方、转发路径和副作用评估。包括发送原文件、派生工件、URL 或可扩大访问的链接。未经允许的敏感外发拒绝，未知载荷或目标而有实际敏感迹象时先核验。 | 本地读取允许范围内的元数据和配置。审批器不发起网络探测或实际发送。浏览器写入或上传缺少真实目标／载荷绑定时保持人工。密钥与宿主硬禁止不能通过人工卡绕过。 |

## 上下文信任与审模数据

- 宿主区分直接用户原始事件、已核验的用户卡片答案及不可信背景。当前 relay 原始事件按序号升序作为群的唯一可信顺序。未入账的原始事件仍按原位置出现。账本只关联背景元数据，条件为当前 `eventSession`、唯一匹配的 `messageId`、来源与文本一致，若有 `eventSeq` 也须一致。缺元数据、重复、错位和跨轮换记录均不提供授权。Bot 转述、引用、定时投递、页面、工具结果、仓库文件和模型生成文字都不授予权限。用户明确引用外部内容时，仅在关联与内容可核对的范围内解释其意图。
- 后台任务、子会话沿宿主已验证的关系定界。用户 fork、跨群和其他私聊各自独立。已观察到而无法核对的潜在用户限制、排队用户输入以及暂无法安全检索的引用或附件触发人工。完整上下文中没有可用授权时用 `unknown`。行为变化或跨 relay 换代使原审核结果失效，同正文和序号也适用。高风险批准须引用实际提供给模型的可信事件，宿主验证类型、归属与版本。
- **分别判断原动作外发与审模载荷外发。** 宿主在每次模型调用前对初始消息、工具返回和累积上下文应用同一策略。按字段选择动作、项目证据和相关用户内容。普通、非敏感动作与项目证据可通过用户配置的审批模型处理，必要时允许完整非敏感命令、实际脚本片段和相关普通用户限制。允许取证不等于允许发送，被审动作的许可也不推出审模载荷许可。使用公开的模型准备与调用接口固定本次适配器和具体路由，路由变化使审查失效。避免把完整日志、环境、文件内容或参数对象无条件复制给模型。
- 密钥、私人数据、可信限制涉及的受保护细节、私域内容和敏感项目正文默认留在宿主。本地可生成类型、范围、可逆性、是否匹配策略等事实供模型使用。确定具体接收方和数据类别均获许可时才发送该类别受限内容，并适用密钥及宿主绝对禁发项。团队默认同 provider、HTTPS、回环默认值或 `prepareCall` 的注册绑定不能独自证明敏感信息可发。当前公开模型接口无法通用确认最终租户和端点，不能凭目录默认值扩大出境范围。由于敏感字段无法发送而影响风险、授权或用户限制判断时记 `protected-evidence`。审批模型能力缺失记 `model-unavailable`。
- 所有输入始终标明来源，结构化只读操作不以文件里的自然语言作为宿主指令。审批卡和审计只用宿主受控文案，禁止回显工具结果、原始参数、模型自由理由、敏感路径和对话。现有隐私外发和支付限制先执行。

## 审批生命周期、原因码与迁移

1. 捕获精确动作和生效模式，审查内存快照记录 Session／relay 身份、许可与配置版本以及关键证据。每次沙箱拒绝后的新提权请求重新取证和审查。每一决策只能结算当前请求，禁止将允许复用于新动作、权限、目标或环境。
2. 结算前重新验证原始调用、待决项、工作目录、解析后的目标及影响裁决的实际读取项。如果用于决定的变更可能改变风险或授权，撤销该结果，留下准确原因。无需证明宿主文件系统与执行原子一致，复验对象限于观察到且决定本次裁决的证据。配置、用户输入、权限或 relay 变化同样作废。宿主最终复验与结算无异步间隙。超时涵盖取证与模型全过程，不为新工具调用重置期限。
3. pending 由单一终态仲裁，人工答复、取消、超时或配置变更抢先后，模型和取证晚到结果均丢弃。原调用已取消时关闭，不开新卡。可人工回退时先开放原私聊宿主入口或群卡，再异步记录。没有可安全作答的人工入口则不执行。**进入自动审查的请求，其每个终态都唯一入审计**：自动允许／拒绝、各种原因转人工、原请求取消记 `cancelled`、被用户输入或模式变化撤下记 `superseded`，单写者保证只写一次；人工回答与模型建议不被误记为自动执行。从未进入自动审查的请求（人工模式、隐私通道、提前取消前未到达自动路径）不写自动审计。审计失败不延迟用户答复。

| 原因码 | 用户可见处置 |
| --- | --- |
| `policy-allowed`／`policy-denied`／`hard-denied` | 单次允许、按政策拒绝或硬禁止。 |
| `policy-manual`／`authorization-insufficient`／`scope-not-narrow` | 本来就需用户作答，或高风险授权／范围不足。 |
| `evidence-incomplete`／`target-unknown`／`protected-evidence` | 无法获知效果，实际目标未知，或需要的数据不能提供给审批模型。 |
| `input-limit`／`model-unavailable`／`model-failed`／`invalid-response` | 输入或取证预算不足、模型不可用、调用失败或输出无效。 |
| `timeout`／`cancelled`／`superseded` | 到期转人工、原请求取消或被用户答复等终态取代。 |
| `stale-context`／`stale-evidence` | 上下文、模式、路由或 relay 变化，或者目标、参数与决定性证据发生变化。 |

沿用 `autoApprove=true` 至 `review` 的迁移、群与 Bot 模式覆盖、子会话原策略恢复。旧审计无风险、授权或原因码字段仍可展示。保留最近 100 条审计以及按归属展示最近 20 条。宿主改动集中在审批、原有动作证据生产点及专用只读取证。仅在用户可见原因需调整时改客户端源码并重建生成文件。

## V2 实现注记（Stage 3，Leia）

1. **准入制废弃，评估制恢复**。`admitShellCommand` 全族删除：不再有任何命令形状准入门槛。`analyzeShell` 只做事实提取（composite/opaque/redirections/替换/遮蔽变量）随载荷交给模型评估——组合命令、构建、测试、依赖操作全部按实际内容进入审查。V1 的 A 表、floor、归一化载荷机制整体移除。
2. **载荷回到「判断所需的事实」**。shell 动作含完整命令、提权标记、cwd 与分析事实；文件工具含目标归属与内容；外部 CLI 含结构化协议载荷。用户内容（含授权与限制）作为证据进入载荷——审批模型是用户为团队配置的路由，用户限制正是模型必须读取的内容。密钥扫描在任何一轮命中都终止整个调用（`protected-evidence`）。
3. **只读取证循环**。`inspect_target`/`inspect_project`/`inspect_context` 三操作：模型以严格 JSON `{"inspect":{...}}` 请求，宿主经公开 fs 服务执行（resolve/lstat/stat/readText/readBytes），预算全链路 30s 共享、最多 6 次、单文本项 32 KiB 截断标记、总输入 96K。`inspect_target` 限定动作 cwd 内的相对目标（拒绝绝对路径、`..`、通配）；`inspect_project` 读取 manifest 脚本与生命周期钩子、锁文件来源域名、npm/pnpm 配置片段；`inspect_context` 取可信行。取证结果作数据回传，命中密钥时整项替换为受保护标记。取证绝不经被审动作权限、不含 shell、不可写。
4. **授权与矩阵**：沿用 V1 基础设施——`verifyAuthorization` 按模型所见上下文核验引用、严格四字段 schema、宿主矩阵独立裁决（low/medium 无论授权放行、high 需 ≥medium 核验授权、critical 拒绝、注入双向门槛进 prompt）。群上下文 relay 原始事件顺序、corroborated 元数据、快照 relay 钉住、私聊/群引用人工、竞态复验全部保留。
5. **新增**：配置版本复验——审查完成后审批模型引用变化即 `stale-context` 失效（覆盖路由变化作废语义）；`scanShell` 重定向目标归入段事实。
6. **`cancelled` 记录口径**（Stage 4 终审修订，替代 Stage 3 注记）：进入自动审查的请求，取消与撤下**写入** `approvalReviews`——原请求取消（shell 终止、会话拆除、宿主取消）记 `cancelled`，被新用户输入或模式变化撤下记 `superseded`；与 allow/reject/manual 同一单写者终态路径，每条仅一次，迟到结果不重复结算。从未进入自动审查的请求不写审计。
7. **外部 CLI**：结构化协议载荷（≥2 键 + 操作键）沿用校验；shell/file 形态复用原生分析路径。协议细化解码（ACP/Codex/Claude 逐型）在 V2 未做专门展开——结构化不足时 `evidence-incomplete` 人工，符合主计划 fail-closed 口径。

验证：端到端自测 12/12——核心场景「无用户原话的 npm test/npm ci 群内放行」、组合命令评估、取证请求→真实读取→裁决闭环、锁文件来源提取、取证范围拒绝（`../`）、预算耗尽 `input-limit`、critical 拒绝、高风险引用放行、Bot 转述不提级；lint 改动文件 0 errors。`external-approval-cwd` 的「trusted callback evidence」用例按 V1 protected-evidence 预期需按 V2 语义重写（外部动作现在进入审查），属预期测试改造面。

## Stage 4 终审定点修复注记（Leia）

终审六项 P1 与两条交叉线索的生产修复，均不改变低/中风险自动路径：

1. **`critical` 无条件拒绝**：矩阵最先判定 `riskLevel === 'critical'` → `reject`/`hard-denied`，不区分 outcome 与授权，人工卡不可覆盖。
2. **symlink 最终包含关系**：`inspect_target` 与 `inspect_project` 对解析后目标执行宿主 `fs.contains(动作目录)`；越界链接只报告存在性/类型并标注 `linkEscapesScope`，内容不读取。
3. **读取硬上限**：项目文件一律经 `readBytes(32 KiB)` 有界读取，超限先拒绝（`FS_TOO_LARGE` 语义）而不入内存；超限作为证据不足标记交给模型转人工。
4. **决定性观察复验**：每次取证为读取内容记录 `sha256+size` 指纹、为 stat/存在性记录 `version+type+size` 指纹；结算前 `reverifyInspections` 经同一公开 fs 服务重算，重解析路径变化（链接重定向）、指纹漂移、读取失败一律 `stale-evidence`。
5. **敏感字段出境边界**：`.npmrc` 正文整体扣留只送键名；`buildInput` 为唯一出境收口，所有送模型字节经 `redactSensitive` 结构脱敏（凭据键值行、URL 密码、Bearer、PEM 块、常见 token 前缀）；`.pnpmfile.cjs`、`pnpm-workspace.yaml`、脚本正文与文件正文同样过该收口。
6. **取消单写者审计**：见上节口径——`cancelled`/`superseded` 与 verdict 同一 `auditFinal` 单写者，早于 in-memory 结算写入，迟到与竞态分支不再重复。
7. **宿主硬规则下限**（交叉线索）：`hardFloorShell` 只识别两类无条件拒绝形态——递归+强制删除指向系统根/家目录/系统盘、同一命令行内凭据材料或环境枚举邻接网络传输动词。模糊形态不进下限，全部留给模型与矩阵；构建/测试/依赖操作不触及此面。
8. **群上下文账本交错**（交叉线索）：上下文按群账本行序发射，可信用户行在精确绑定（eventSession+messageId+文本+可选 eventSeq）处原位升级；未入账事件按序尾接。授权时序与注入判断不再受「用户行整体前置」的重排影响。
