# 收件箱：所有 Bot 和群聊里等你处理的事

- 日期：2026-11-25

## 为什么

以前「等你处理」有四处各算各的：桌面侧栏、手机「需要你」页、手机推送、桌面系统通知。四处的清单不一样：邮件外发、电脑操控、被模型失败卡住的 Bot、暂停的派活和群聊，有的地方算，有的地方不算；群里成员问的问题，侧栏的群行看不见。同一件事，手机上有，桌面上没有。

根因是没有一份由宿主给出的清单。现在宿主从已有状态派生一份，所有界面都读这一份；再加一个收件箱页，把它们放在一处处理。

## 已定的行为

### 一份清单，由宿主派生

- `ds-bot/src/host/inbox.js` 的 `inboxView()` 只从现有状态派生，不加新记录。随 `live()` 下发为 `inbox: { count, counts, items }`。
- 条目：`{ id, kind, group, ref, at, botId?, roomId?, sessionId?, taskId?, text?, … }`。`id` 是 `kind:ref`，`ref` 是来源自己的 id，稳定。
- 三组，按这个顺序处理；组内等得最久的在前：

| 组 | 类型（`kind`） | 来源 |
|---|---|---|
| 等你决定（`decide`） | `approval` 工具审批（私聊、群聊、后台任务） | `approvalsView()`，不含模型还在审的、这个窗口不能答的 |
| | `question` 提问、`view` 表单卡 | `state.questions`、`state.views`；已归档段里的不算 |
| | `secret` 密钥、`connector` 连接器、`mail` 邮件外发 | 各自请求里 `pending` 的 |
| | `computer` 电脑操控、`handoff` 浏览器或电脑交给你 | `computerLive()`、`browserChannel.holdSnapshot()` |
| | `goal` 群目标等你 | `room.goal` 进行中且 `idle` |
| 需要修复（`fix`） | `blocked` 被模型失败卡住、`model` 还没选模型 | `bot.blocked`、`bot.kickoff` |
| | `paused` 派活暂停、`room-paused` 群聊接力到上限暂停 | `pausedWorksView()`、`room.idlePaused` |
| Bot 的建议（`suggest`） | `learning` 技能、AGENTS.md 提议 | `learningView()` |

- 群里问的卡带 `roomId`，属于这个群，不算成员私聊的。后台任务里的卡带 `taskId`，不挡私聊。
- 别的模块可用 `rt.addInboxSource(fn)` 扩展自己的条目；条目按同一格式校验，Bot 和群都不在的丢掉。
- 变化信号：存盘、审批、浏览器接管；电脑操控和学习提议自己调 `rt.inboxChanged()`。`rt.onInboxAdded(fn)` 只报新出现的条目；启动后第一次只记下已有的，重启不重报。

### 读这份清单的地方

- 桌面侧栏：Bot 行、群行和收起的分组的琥珀点、状态行（等你批准 / 等你回答 / 等你处理 / 已暂停 / 需要修复）。挡住当前对话的条目盖过「工作中」；后台任务的、建议和修复只在空闲时显示。
- 收件箱页。
- 桌面系统通知和程序坞角标：每个对话一行，条目 id 变了就提醒一次，正文只写「等你处理」。
- 手机「需要你」页、角标、列表标记：读 `inbox`；连没有 `inbox` 的旧宿主时，按原来的算法从团队状态算。
- 手机推送：每个新条目推一条，按类型分；没开预览时不带原文。

### 入口

- 宽栏：顶栏 `+`（新建）按钮旁边的极简图标按钮，有待处理时右上角显示小巧计数角标，不占用侧栏列表空间。
- 窄栏：底部 `+`（新建）按钮上方的同款圆形图标按钮，带计数角标。
- 点开在主区打开收件箱页（`ui.inbox`，和新建聊天一样盖在对话列上）；再点入口、点右上角关闭或打开任何对话都会收起它。

### 页面

- 顶部：主标题、「等你处理 / 新回复」分段控件与关闭按钮；下方为按 Bot / 群聊筛选的胶囊条（只有一个来源时不显示）。
- 「等你处理」分三组，组头带语义状态点与计数。每条直接渲染为一张扁平卡片，无需二次点开，也不做卡片嵌套：顶条一行显示来源头像、Bot/群名、类型、等待时长与「在聊天中查看」；主体直接铺平聊天里同一个交互卡片（审批、提问、表单、密钥、连接器、邮件、接管、派活暂停、学习提议的差异）。在这里或聊天里任一处处理，两边一起消失。群暂停和被模型卡住的 Bot 直接显示单行文案与主操作按钮（继续 / 重试）；换钥匙、登录、换模型在聊天里的失败卡上做。
- 处理后该卡片先显示「已处理」约 1 秒再收起，避免下一项在指针下跳走。
- 键盘：↑↓ 切换卡片焦点，Esc 直接关页。
- 「新回复」：有没读回复的 Bot 私聊或群聊各一行；点开进入聊天，进入即已读。

### 隐私

- 收件箱只在用户自己的界面里。摘要不含密钥值；手机和网页远程端看到的不比团队状态里已有的多。
- 设置 → API（对外统一 API）不开放收件箱。

## 不做什么

- 不加任务对象，不做看板。
- 不做「全部允许」：每条审批单独决定。
- 通知里不带内容原文。
- 不做稍后提醒。

## 已知限制

- 「新回复」没有「标为已读」：DSH 只在打开对话时清未读，没有不打开就清的接口。
- 聊天页没有「← 收件箱」返回按钮；回收件箱用侧栏入口。
- 很长的表单卡在收件箱里展开也是全尺寸，可点「在聊天中查看」。
