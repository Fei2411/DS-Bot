# IM：在聊天软件里和 Bot 说话

- 日期：2026-11-04
- 相关：#904；[群聊](2026-10-07-group-chat.md)、[浏览器、搜索、密钥和连接器](2026-10-08-browser-and-secrets.md)、[手机 App](2026-10-24-mobile-app.md)

## 为什么

用户离开电脑时，Bot 还在干活，但只能回到 DS Bot 里才能找它们。大多数人整天开着微信、飞书、Telegram 这类聊天软件。IM 让用户在那里和某个 Bot 或某个群对话：消息进 Bot 和群，Bot 的回复和卡片发回聊天软件。

取舍：

- **IM 是通道，不是成员。** 聊天软件里的机器人（下称「IM 机器人」）绑到一个 Bot，不进 Bot 名单，不占角色和权限。用户在 IM 里说的话就是用户的话，和在 DS Bot 里打字一样进 Bot 当前的那一段。
- **DS Bot 自己做。** 连接、绑定、发什么、设置页都归 DS Bot；消息直接进 Bot 和群，不经过 DSH 自己的会话。插件版和桌面应用用同一份代码。各平台的协议代码有一部分来自 MIT 许可的开源实现，见 `NOTICE`。
- **电脑只往外连。** 只用平台的长连接或长轮询接口，不需要公网 IP，不开端口。

## 已定的行为

### 平台

| 平台 | 连接方式 | 要填的 | 私聊 | 群 | 卡片怎么答 |
|---|---|---|---|---|---|
| 微信 | 腾讯 iLink，扫码绑定，长轮询 | 扫码 | 只和扫码的账号 | 不支持 | 回复编号 |
| 飞书 / Lark | 长连接 | App ID、App Secret；选飞书或 Lark | ✓ | @ 机器人 | 卡片按钮 |
| 钉钉 | Stream 模式 | Client ID、Client Secret | ✓ | @ 机器人 | 回复编号 |
| 企业微信 | 智能机器人长连接 | Bot ID、Secret | ✓ | @ 机器人 | 卡片按钮 |
| QQ | 官方机器人 Gateway | App ID、App Secret | ✓ | @ 机器人 | 回复编号 |
| Telegram | Bot API 长轮询 | Bot token | ✓ | @ 机器人或回复它 | 按钮 |
| Discord | Gateway | Bot token | ✓ | @ 机器人 | 按钮 |
| Slack | Socket Mode | App token、Bot token | ✓ | @ 机器人 | 按钮 |

### 添加和绑定

- 设置 →「IM」：列出已添加的 IM 机器人，每个一行：平台、账号名、状态（已连接 / 连接中 / 连不上和原因）、绑定的 Bot。
- 添加：选平台，填上表的字段（微信是扫码），选绑定的 Bot。DS Bot 先向平台核对一次，核对通过才保存。
- 一个 IM 机器人绑一个 Bot：所有私聊都进这个 Bot。改绑定、停用、移除都在这一行里。
- 平台凭据存进 DS Bot 的密钥（设置 → 密钥里能看到），不给任何 Bot 用；发给模型前照常替换。移除 IM 机器人时一起删掉。
- IM 机器人在聊天软件里的群：配对过的账号在群里第一次 @ 它时，这个群出现在它那一行里，用户给它选一个 DS Bot 的群（也可以选一个 Bot）。没选之前，IM 机器人在群里回一句「这个群还没绑定」。
- 绑定的 Bot 或群被删掉后，对应的私聊或群回到「还没绑定」。

### 配对：只认允许过的账号

- 一个账号第一次给 IM 机器人发消息（私聊，或在群里 @ 它），设置 →「IM」里出现「谁想连接」，带平台上的名字。用户点「允许」才算配对；点「拒绝」就去掉这条请求。
- 没配对的账号：消息不进任何 Bot；IM 机器人只回一次「已发出连接请求」。按钮也只认配对过的账号。
- 微信扫码的那个账号自动配对：扫码本身就是在电脑上确认的。
- 配对过的账号可以在设置里移除，之后它的消息不再进 Bot。

### 消息怎么走

- 私聊：消息进绑定 Bot 当前的那一段，和在 DS Bot 里发消息一样排队（Bot 忙时等这一轮做完）。聊天记录里这条消息标出来自哪个平台。
- 群：@ IM 机器人的那条消息去掉 @ 后进绑定的 DS Bot 群，和用户在群里发言一样。
- 图片按图片发给 Bot；文件按附件发给 Bot；平台给了语音转写时发转写的文字，没给时把语音当文件发。
- Bot 在忙时，支持的平台显示「正在输入」。
- `/stop`：停下绑定的 Bot（或群里全部成员）正在做的活。

### 什么发回聊天软件

- 回复只发给发起本轮消息的 IM 连接和会话；同一 Bot 绑定的其他聊天不接收。
- 网页、手机 App、Bot 之间的消息、定时任务及来源不明的轮次不向 IM 外发。
- 同一轮混入其他来源后，不再向 IM 外发；后续消息不能把混合轮次重新认领。
- 群成员回复跟随发起这轮群工作的来源；系统提示和事件行不发。
- 提问、审批、密钥提示、视图卡沿用同一来源规则。通过 IM 回答提问卡的续答，按被接收的卡片答案回到该 IM 会话；网页和手机答卡不继承 IM 来源。
- 回复按平台格式发送；超过平台单条限制的拆成几条，按顺序发。

### 卡片

- **提问卡**：发问题和选项。有按钮的平台点按钮；没有的回复编号（多选用空格隔开几个编号）。在任何一端答过以后，卡片在其他地方失效；能改消息的平台把按钮换成答案。
- **审批**：Bot 自己的聊天和群里成员的审批都发。按钮或编号：1 允许一次，2 拒绝。DS Bot 里的审批卡和 IM 里的哪个先答哪个生效，另一个随即失效。
- **密钥卡**：不在聊天软件里填（值会留在平台的服务器上）。IM 里只说哪个 Bot 要哪个密钥，请用户到电脑或手机 App 上填。
- **视图卡**：发文字版；要回复的视图请用户到电脑或手机 App 上回复。
- 编号只答这个聊天里最新的那张还开着的卡；其他时候数字就是普通消息。

### 运行

- 只有占着团队锁的那个 dsh 连 IM；只读窗口不连，接管锁之后再连。所以每条回复只发一次。
- 连接断了自动重连，间隔逐步拉长；状态和最近一次错误显示在那一行里。
- 发送失败：平台明确拒绝的（凭据失效、超出平台的回复时限或额度）不重发，显示在那一行里；没发出去的（断网）等连上后按顺序补发。发没发出去不确定的不重发，避免同一条发两遍。
- 已经发过的卡片记在数据目录里，重启后不重发。

## 不做什么

- IM 机器人不进 Bot 名单，不派活，不当外部执行者（这部分归「接入本地 Agent」）。
- 不让没配对的人和 Bot 说话；不把群里其他人的话转给 Bot。
- 不在聊天软件里填密钥、管理团队、改设置。
- 不接需要公网回调地址的接口，不接非官方协议的平台。

## 已知限制

- 微信和 QQ 只允许在用户发消息后的一段时间内回复，额度也由平台定；超出后的回复发不出去，设置里显示原因，用户再发一句后恢复。
- 微信只能和扫码的那个账号私聊，不支持群。
- 钉钉、QQ、微信没有卡片按钮，用编号回复。
- 电脑关机或睡眠时，消息等平台保留；平台不保留的就收不到。
- 手机 App 里还没有 IM 设置页。
- Bot 私聊里当前这一段的用户消息由 DSH 画，暂时不显示「来自 …」；群聊和更早的段里显示。

## 变更

- 2026-11-13：IM 改为只回复来源会话；混源与来源不明时不外发。
