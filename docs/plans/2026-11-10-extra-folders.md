# 额外工作文件夹：一个 Bot 同时在几个文件夹里工作

- 日期：2026-11-10
- 相关：Issue #1297

## 为什么

一个 Bot 常常同时负责几个项目。只有一个工作文件夹时，它要在项目之间来回切换，每切一次换一段对话。用户希望 Bot 和群聊能同时在几个文件夹里工作。

DSH 的 `workspace-write` 把写入限制在 Session 自己的文件夹（Session 建立时的 cwd）。DSH 的额外可写目录（`additionalWritableRoots`）只能给整个部署配置，插件 API 里没有按 Session 配置的入口。DS Bot 按规定只用插件 API，所以这样做：

- Session 仍然只有一个文件夹，换段规则照旧。
- 文件工具写到额外工作文件夹时，DSH 的沙箱先拒绝，模型带 `sandbox_permissions` 重试，DSH 发出审批请求；DS Bot 在 `approval/request` 里先看这次调用要改的路径，全部落在 Session 的文件夹或它的额外工作文件夹里，就直接批准这一次调用。
- 命令行的路径要等命令真正运行才知道，所以 shell 命令写额外工作文件夹时照常请用户批准。

## 已定的行为

### 设置

- Bot 和群聊在工作文件夹之外各有一份额外工作文件夹列表（`extraDirs`），最多 8 个。设置页「工作文件夹」卡片里逐个列出，可以添加和移除；添加用和工作文件夹相同的文件夹菜单。
- 保存的是真实路径，按给出的顺序，去掉重复。规则和工作文件夹相同：完整路径、已存在的文件夹、不含 DeepSeek Harness 或团队的数据。总工作区也可以作为额外工作文件夹。
- Bot 用 `update_bot` 的 `extra_dirs` 改自己的列表；Main Bot 可以改别的 Bot 的，也可以用 `update_group` 的 `extra_dirs` 改群的。参数是整份新列表，空列表清空。Bot 新加的每个文件夹都先请用户批准一次，规则和设工作文件夹相同；用户在设置页里改的直接生效。
- 改列表不换段，Bot 从下一步起就能写新的文件夹。
- 复制 Bot 时一起复制还存在的额外工作文件夹。

### 哪些文件夹算数

- Bot 自己的聊天：Bot 的额外工作文件夹。
- 群里没有设群文件夹：成员自己的额外工作文件夹加上群的额外工作文件夹。
- 群里设了群文件夹：成员只用群的额外工作文件夹，和「群的文件夹对每个成员都有效」一致。
- 群自己的转发 Session 没有额外工作文件夹。

### 写入

- `write`、`edit`、`apply_patch` 带 `sandbox_permissions: "danger-full-access"` 请求升级时，DS Bot 把要改的每个路径（`apply_patch` 里的新增、修改、删除和移动目标）按 Session 当前目录解析成真实路径；全部落在 Session 的文件夹或额外工作文件夹里，并且都不在数据目录里，就批准这一次调用，用户看到的审批卡也就不出现。有一个路径落在别处，整次调用交给用户决定。
- 只有 `workspace-write` 的 Session 才这样批准；只读的 Session 写额外工作文件夹仍然要用户批准。
- 读文件本来就不受沙箱限制，照常进行。
- `working_directory` 进入额外工作文件夹时只移动这段对话，Bot 的工作文件夹保持原样，和进入工作文件夹里面的子文件夹相同。
- 系统提示词里有一节「Your extra folders」，列出这个 Session 的额外工作文件夹，说明用文件工具写入、带 `sandbox_permissions` 重试的做法。没有额外工作文件夹的 Session 没有这一节。
- `list_bots` 显示每个 Bot 和群的额外工作文件夹。

### 隐私 Bot

- 隐私 Bot 只在自己的文件夹里工作：有额外工作文件夹的 Bot 要先移除它们，才能设为隐私 Bot；隐私 Bot 的设置页也就不显示这份列表。
- 额外工作文件夹和工作文件夹一样，不能与隐私 Bot 的文件夹互相包含；设为隐私 Bot 时，它的文件夹也要和别的 Bot、群的额外工作文件夹分开。

## 不做什么

- 一个 Session 同时有几个 cwd：DSH 的 Session 只有一个工作目录。
- 改 DSH 的部署级可写目录：那会对所有 Session 生效，越出这个 Bot 的范围。
- 自动批准 shell 命令：命令里的路径在运行前读不准。

## 已知限制

- 子 agent 的 Session 不继承额外工作文件夹，子 agent 写那里时照常请用户批准。
- 自动批准在审批时检查路径，和 DSH 自己的包含检查一样，挡不住审批之后才换掉的链接。
- 自动批准走 DSH 的审批流程。DSH 自带的两个权限预设都适用：`workspace-write`（询问）由 DS Bot 批准，`danger-full-access` 本来就能写任何位置。自定义预设若是 `workspace-write` 加「从不询问」，DSH 在询问之前就拒绝升级，这时额外工作文件夹只能读；要写就换成询问的预设。
- 文件面板显示 Session 自己的文件夹；额外工作文件夹里的文件用完整路径打开。
