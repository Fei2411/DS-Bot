# 群聊任务面板

- 日期：2026-11-12
- 相关：Issue #1441

## 为什么

一个群里可能同时有几个 Bot 在干活，消息刷得快，用户没法从聊天里看出谁在做什么、做到哪一步。派出去的活、进展和结果散在聊天记录里，想追加一句需求还得翻回去找对应消息。任务面板就是群自己的答案：一个任务一行，由干活的 Bot 显式登记，显示在群详情抽屉里。

## 已定的行为

- 任务属于一个群和一个成员。字段：id、成员、一句话目标、状态、开始与最近更新时间、最新进展、结果摘要、用户备注。
- 状态：`active` 进行中、`review` 待审、`blocked` 阻塞、`done` 已完成、`cancelled` 已取消。前三个算进行中，后两个进历史。
- Bot 用新工具 `group_task` 登记自己的任务：`open` 接活时开、`update` 期间更新、`complete` 完成时带一句结果摘要、`cancel` 停下时取消、`show` 看当前面板。登记必须显式，不从聊天消息里解析。
- 只有登记任务的 Bot 能更新、完成它；群管理员和 Main Bot 可以取消别人的任务，任务负责人总能取消自己的。
- 用户不在面板上直接改状态。补备注（追加需求或改目标）会把备注记在任务上，并以用户消息 `@负责人 …` 发进群，由群引擎叫到对应 Bot，在干活的那个会话里收到；面板上的取消是面板自己的动作。
- 任务存在 `room.tasks`，和群目标、群记忆、工作目录放在同一个 room 对象里，随 `state.json` 一起保存：删群就没了，重启后和群本身一样还在。
- 已完成和已取消的任务是终态，不能重新更新或完成；历史不按数量自动删除。文本都压成一行：目标 200、进展 300、结果 2000、备注 500、取消原因 500 字。
- 面板在群的详情抽屉里：先列进行中（成员、状态、目标、最新进展、开始时间），历史可展开，显示结果摘要或取消原因。面板读的就是应用其余部分读的同一份状态，Bot 改状态后不用刷新页面就会跟着变。

## 不做什么

- 不做跨群总面板，不做工时/时间跟踪，不扩展到代码改动展示（那是 #1446）。
- 不解析聊天消息猜任务和状态。

## 已知限制

- 只有 Bot 能开任务；用户想派活仍在群里说一句，由 Bot 自己登记。
- 备注以 `@负责人` 的消息下发，所以群引擎按 @ 规则叫人；如果群当时被暂停/停止，消息会留在群里等它恢复。
- 历史随群数据保留，只有删除群时一起删除。
