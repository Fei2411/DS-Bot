# 自托管部署笔记与手机页面规划（2026-11-03）

这份文档记录我们在一个真实自托管实例上做的事：**哪些值得回流上游、哪些属于部署层不该进仓库**，以及**手机页面该怎么补**（对应 #845、#834、#839、#846）。

背景：把 DS Bot 跑在一台笔记本（WSL）里，通过反向隧道 + nginx 暴露成一个 HTTPS 站点，日常用手机看结果。用下来最痛的两件事——**移动端打不开**和**跑完没通知**——正好对应下面两部分。

---

## 一、我们做的增强（清单）

标注：✅ 已提 PR ｜ 🚫 不建议上游（部署层）｜ 💡 可以做成文档或可选能力

| # | 能力 | 做法 | 结论 |
|---|---|---|---|
| 1 | **推送到手机** | 新增 `notify_user` 工具，通道 Bark / ntfy / ServerChan / webhook，配置读 `<DSH_HOME>/bot/notify.json`，环境变量回落 `BARK_URL`、`NTFY_TOPIC`、`SERVERCHAN_KEY`、`PUSH_WEBHOOK` | ✅ PR #842 |
| 2 | **定时巡检** | 直接用内置 `schedules`（cron/daily/weekly），不另写调度 | 🚫 原版已有，无需改 |
| 3 | **公网入口** | 反向 SSH 隧道 + nginx 反代 + Basic Auth + Let's Encrypt | 🚫 部署层 |
| 4 | **进程自愈** | Windows 侧一个看门狗，按端口探活，挂了 15 秒内拉起（DSH Web、隧道、worker 池、研究原型各一条） | 🚫 部署层，但值得写进文档 |
| 5 | **版本隔离** | Bot 用的 DSH 单独装一份（不同 rc），不污染主工作环境 | 🚫 但值得写进文档 |
| 6 | **队列桥** | 服务器侧任务队列 + 3 个 worker + 租约重试；每个任务一个 `job/<id>` 分支，成功才 `--ff-only` 合并 | 💡 与 Bot 模型有边界，见下 |
| 7 | **增量巡检** | 巡检结论写进 Bot 记忆，下一轮只报差异；无变化不发消息 | 💡 可做样例 |

### 边界：队列桥 **不能** 驱动 Bot

`dsh --profile headless` 加载本插件会停在 `pending (waiting for services: sessionController, workspaceRegistry, connection)`，**headless 跑不了 Bot**。所以队列 worker 只适合跑普通 dsh 任务；Bot 必须活在 Web 里。

### 一条经验：巡检要「安静」

一开始每小时一份简报，一天 24 条内容几乎一样，真正的变化被埋掉了。改成**只有变化才说话**（+ 每天一条总览）之后才有用。同理，健康检查在正常时应该完全不出声。

## 二、手机页面规划

目标一句话：**iPhone Safari 打开就能读、能发、能收到结果**。

### 1. 布局（对应 #834 / #845）

- 根容器用 `100dvh`（不是 `100vh`，Safari 地址栏会吃掉高度），配合 `env(safe-area-inset-*)` 处理刘海和底部横条。
- 输入框 **sticky 贴底**、始终可见；消息区独立滚动，主文档本身不滚。
- 侧栏窄屏折叠成抽屉（`transform: translateX`），**不参与 grid 轨道**——#834 里 0px 轨道的根因就是折叠后仍占列宽。
- 断点建议 `640px / 1024px` 两档，先窄屏优先，再向上加栏。

### 2. 消息渲染（对应 #845「历史区空白」）

- 窄屏下避免对整段历史做重排：首屏只渲染最近 N 条，向上滚动时按需加载。
- 消息气泡 `min-width: 0` + `overflow-wrap: anywhere`，防止长链接/代码块把容器撑破。
- 代码块横向滚动而不是撑宽页面。

### 3. 输入与发送（对应 #839）

- Enter 发送、Shift+Enter 换行；中文输入法组合期（`isComposing`）不触发发送。
- 空输入框按 Enter 时，把排队中的消息送出去（#839 的行为）。
- 发送按钮在键盘弹起时不被遮住：监听 `visualViewport` 调整底栏位置。

### 4. 附件与语音

- 相册拍照走 `<input type="file" accept="image/*" capture>`，前端压缩到长边 2000px 再上传。
- 上传中显示进度，失败可重试。

### 5. 缩放与字号（对应 #846）

- 不锁 `user-scalable=no`（那是无障碍倒退）；用 `viewport-fit=cover` + 相对字号。
- 提供「跟随系统字号」开关，字号用 `rem` 计算。

### 6. PWA 与通知

- `manifest.json` + 192/512 图标 + `display: standalone`，桌面添加入口正常。
- 站内推送能到最好；**到不了就用外部通道兜底**（Bark / ntfy），也就是上面第 1 条的能力——iOS 上这条比 Web Push 可靠得多。

### 7. 弱网

- SSE 断线重连用指数退避（1s → 30s 封顶），顶部显示「重连中」状态条，不要把错误当成「消息发不出去」。

### 验收标准

- iPhone Safari（真机，非模拟器）+ Android Chrome 各一张截图；
- 首屏可见最近消息、输入框可见可点、发送后 2 秒内出现自己的气泡；
- 旋转横屏后布局不破、输入框仍在底部；
- 断网 10 秒再恢复，能自动接上且不丢消息。
