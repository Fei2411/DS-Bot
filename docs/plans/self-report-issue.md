# DS Bot bug reporting

When a user explicitly asks to report a DS Bot bug or confirms they want to report a suspected DS Bot defect, the bundled `report-ds-bot-issue` skill checks for duplicates when possible and drafts a public bug report. Routine user code, shell, third-party API, provider/network, config, and permission errors are excluded, and the Bot asks before preparing a draft unless the user already requested one. It routes security reports to GitHub's private advisory form. The host adds DS Bot/DSH versions and OS, strips known secrets and home paths, and returns the exact draft for review. Logs, images, and chat transcripts are not collected automatically.

The Bot calls `show_view` in its own chat with the returned draft and a short-lived reference (`prepare_ds_bot_issue` is hidden in group and background-task sessions). The host verifies the preview matches, binds the draft to the existing confirmation card, and durably claims that card before sending a GitHub write. A typed reply, dismissal, rejection, replacement or replay cannot authorize that write.

The host uses the Bot's existing GitHub connector credential only for `Fei-Craft/DS-Bot`, and respects per-Bot access, read-only mode and sign-in. It returns the issue URL or, if it cannot publish, a capped prefilled GitHub link for manual submission. An uncertain result is not retried automatically. No new client UI or connector setup is introduced.
