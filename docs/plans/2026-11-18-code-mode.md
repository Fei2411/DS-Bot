# 可选代码模式

默认关闭。不改 Bot 的 standard 预设选择，不改 DSH。
代码模式要求 DSH 0.2.2-rc.1 或更新版本；开关关闭时主插件不导入独立的 `ds-bot/code-mode` 入口，因此不影响旧版宿主。

只接管程序外层 call/result 的 Session 记录，在公开 PTC executor 完成后裁剪结果，再记录和返回，避免 guard 拒绝等绕过 post-execute 的结果漏裁剪。原生调用和所有内层调用的管道与日志仍交给公开 executor。canonical 值不变，不改写权限策略的决定。

`ds-bot/code-mode` 是独立的公开插件入口。它在自己的作用域注册一个 executor，组合公开的 `NativeToolExecutor` 和 `PtcExecutor`，不用 DSH 安装目录或私有成员。普通连续调用交给 native；`run_code` 交给 PTC，作为屏障执行。内层工具仍经过 DSH 权限、guard、取消、日志和结果管道。

- `mode: hybrid`（默认）：普通工具和 `run_code` 同时提供。程序只绑定文件、搜索、shell、web 和 `mcp__` 工具。团队消息、群中继、agent、goal、todo、workflow、skill 和 job 工具只走原生调用。
- `mode: code-only`：只提供 `run_code`，全部可见工具都在程序里调用。
- `maxResultChars: 8000`：模型可见的程序结果文本上限，按 Unicode 码点计数，最小 256。超出保留头尾，标明省略的准确字符数，并要求在程序中筛选。成功、错误和日志里的外层结果使用同一裁剪。内层 canonical 值和图片附加上下文不裁剪。

SDK 省去完整输出类型。hybrid 已有原生 schema，程序 SDK 只列工具名和常用工具的简短结果形状，参数沿用同名原生工具，不重复参数类型或描述。code-only 保留一行工具说明和参数类型。未知输出为 unknown，不承诺完整字段。hybrid 中不列原生专用工具，code-only 中全部列出。模型应在一次程序里定位、批量修改、验证，只返回摘要。一个简单操作用原生工具。

开关在 `ds-bot/cordis.patch.yml` 的 `bot` 行，`config.codeMode.enabled` 默认为 false。App 的当前 profile 也加载这个 bundle；不要修改停用的 `app/engine/` bundle 或 DSH 的预设文件。要启用，在自己的 profile 的 `cordis.patch.yml` 中设置：

```yaml
- id: bot
  config:
    codeMode:
      enabled: true
      mode: hybrid
      maxResultChars: 8000
```

修改开关后重启 engine。只在 Bot 自有会话（含成员群聊会话和后台任务会话）的 Agent 作用域中挂载 executor，纯 `group_relay` 群主会话与普通 DSH Agent 保持原生执行器不受影响。Session 离开 Bot 归属、插件卸载或 `ptcRuntime` 重载时，会为存活的 Agent 恢复 `NativeToolExecutor`，避免 DSH fail-closed 机制导致旧作用域不可用；重新归属或重载后可再次接管。关闭时不加载可选 executor 包，也不增加 runtime 依赖。多文件补丁还需在所选 agent 预设的 `tool-fs` 行设置 `config: { applyPatch: true }`；这个开关不会改写宿主的文件工具配置。不在同一作用域再挂原生或 PTC executor；祖先 native executor 可以保留。

团队主运行时始终运行在父级 `ctx` 上，代码模式作用域通过独立的可选 `ptcRuntime` 子插件挂载。启用开关但宿主未提供 `ctx.ptcRuntime` 时，团队仍正常启动并沿用普通 executor，并在启动日志和设置中的 Feedback 诊断报告提示启用 `ptc-runtime`（`@deepseek-ai/dsh-ptc-runtime-node`）或关闭 `bot.config.codeMode.enabled`；若 `ptc-runtime` 随后异步就绪，代码模式会自动生效；若 `ptcRuntime` 停用或重载，仅卸载代码模式作用域并恢复原生执行器，不影响整个 Bot 团队。

隐私隔离方面，`privacy.js` 同时拦截 `apply_patch` 的全部源/目标路径（`Add/Update/Delete File` 与 `Move to`）以及 `run_code` 的代码文本与路径字面量（含 Windows 转义反斜杠归一化），防止越权读写隐私 Bot 目录、共享状态、API 凭证或密钥文件；同时，团队中存在其他隐私 Bot 时，`run_code` 也会拦截直接导入或调用宿主文件系统/进程逃逸模块（`fs`、`node:fs`、`fs/promises`、`child_process`、`node:child_process`、`process.binding`、`process.dlopen`、`process.getBuiltinModule`），要求通过受 `privacy.js` 与 DSH 策略管辖的 `tools.*` 访问文件。隐私 Bot 在自身目录之外或 `danger-full-access` 下执行 `apply_patch` / `run_code` 须经用户审批。与 `docs/plans/2026-10-27-private-bots.md` 一致，`run_code` 外层检查属于静态扫描与内层工具策略防线，并非操作系统/内核级只读隔离边界；针对对抗性代码混淆或动态构造的底层绕过，实际文件读取隔离仍受宿主平台与 `dsh-sandbox` 能力约束。

独立 headless overlay 应禁用根 `tool-executor-native` 和 `tool-executor-ptc`，插入 `ds-bot/code-mode`，并给 `tool-fs` 设置 `applyPatch: true`。DSH 包和 schemastery 与其他宿主接口一样声明为 `peerDependencies: "*"`，由宿主提供，不携带固定版本的执行器副本。单元测试由 `npm run harness` 提供 App 版本的包。独立烟测安装准确的 CLI 版本和 `npm pack` 生成的插件包，避免依赖开发目录的 peer 跳过设置。要求 TypeScript PTC runtime，沿用宿主的函数体、REPL 或 Script 语法，不增加自己的 eval 或 sandbox。

群聊在 hybrid 中仍直接调用 `group_relay`。code-only 沿用旧 PTC 中继包装。工具注册兼容层只在列表仅有 run_code 时保留代码专用列表；hybrid 仍补齐迟到注册的团队工具。

测试 SDK 比较使用原基准 23 个工具的参数 schema 和描述；fixture 的输出 schema 统一为 JSON，避免与安装包私有实现耦合。因此该字节比较是固定 fixture 上的保守比较，不等同于原 smoke 的完整 SDK 字节数。真实首步输入与任务收益另做基准。
