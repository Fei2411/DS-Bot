# 事件驱动与统一待处理（Event-Driven Architecture）

- 日期：2026-11-19
- 相关：#781（回合/任务卡死看门狗）、#784（跟踪 PR）、#921（Work Center 提案）、#1665（本机脚本推送事件唤醒 Bot）、Discussion #1819（事件探针与统一外部事件设计）

## 为什么

1. **外部世界的变化进不来。** 过去 Bot 只在用户发消息、Bot 之间派活、群聊推进或固定定时到点时才动。盯着 PR 评审、CI 失败、新邮件、目录文件或本机脚本信号，只能靠定时任务每隔几十分钟做一次完整模型调用，没变化也白烧 Token。
2. **分散触发不可见、不可停。** 派活、群任务板、定时和卡死回合散在各模块，后台回合卡住没人发现（#781），高频事件缺少折叠与熔断，多 Bot 同时干活时审批和提问分散在多个聊天里看不过来。
3. **外部载荷必须和用户指令隔离。** 外部评论、邮件、RSS 或本机脚本推来的数据不可信，直接当用户消息灌进会话会带来提示词注入与越权风险。

## 已定的行为

### 1. 统一事件账本（按月与隐私分本）

- 事件是一条不可变记录：来源（`source`）、信任级别（`user | team | external`）、线索键（`threadKey`）、实体折叠键（`entityKey`）、事件类型（`eventType`）、去重键（`dedupeKey`）、摘要、正文与元数据。
- 复用 `ledger.js` 只追加存储，按月分本（`events-YYYY-MM.jsonl`）并按保留期自动清理旧月，防止长期运行撑爆内存。
- 隐私 Bot 的探针与事件写入独立分本（`events-priv-<botId>-YYYY-MM.jsonl`），不进入共享账本；`<home>/events`、`<home>/api-tokens.json`、`<home>/api-endpoint.json` 与事件账本全部纳入 `privacy.js` 路径围栏。
- 所有事件先落盘再投递；超长正文复用 `attachLong` 存为文件，模型按需通过 `read_event` 读取全文。

### 2. Pull 机械探针 + Push 本机推送双轨接入

- **仅持锁宿主运行**：通过 `home-lock.js` 联动，只有持有 `state.lock` 的主进程跑探针、接收本机 Push 写入和跑看门狗；只读窗口仅查看账本与状态。
- **五类机械探针（零模型开销）**：
  - `github`：复用 GitHub 连接器凭据，`If-None-Match` 条件请求实现 `304` 零唤醒，自动过滤当前账号自身事件防死循环，`401/403` 自动暂停并提示重新登录。
  - `mail`：复用已连邮箱账号，自动过滤自身发信地址，支持发件人过滤。
  - `folder`：`fs.watch` 防抖 + 文件哈希比对，识别新增、修改与删除。
  - `http`：强校验 `https://`，拒绝 loopback 与内网地址防 SSRF，支持 `ETag`/`Last-Modified`/SHA-256 变化检测与 RSS/Atom 解析。
  - `command`：受限目录与超时下的本地命令检查，输出经密钥脱敏。**硬规则：仅用户本人可在界面创建、修改或启停，任何 Bot（含 Main Bot）一律禁止通过工具触碰 `command` 探针。**
- **首次基线**：新探针第一次检查只建立基线，不补发历史旧记录。
- **本机 Push 入口（`POST http://127.0.0.1:<port>/v1/events`）**：默认关闭，仅绑 `127.0.0.1`，Token（`dsb_live_<keyId>_<secret>`）仅以加盐 SHA-256 哈希存于 `<home>/api-tokens.json`，只接受 `Authorization: Bearer` 请求头（拒绝 URL 参数传 Token），对隐私 Bot 目标严格返回 `404`。

### 3. 快慢路径、订阅直通与不可信信封

- **稳定身份路由**：订阅绑定 `botId`、`roomId` 或后台任务 `taskId`（不绑定会随换段失效的 `sessionId`）。命中活跃或已完成（`drive` 模式）的后台任务时直接投递到该任务段，绕过前台；已停止的任务绝不擅自复活，转入死信待人处理。
- **代码快路径（零模型开销）**：按来源、线索（支持前缀 `*`）、类型、发送者、关键词过滤；支持安静时段（`defer` 暂存合并或 `drop`）、同实体折叠（`coalesceMs`）与每小时频次熔断（超限暂停订阅并产生告警，不悄悄丢弃）。
- **不可信信封与 Mandate**：外部事件以 `role: 'event'` 投递，正文头部明确标注不可信数据边界与 Mandate 授权范围；推测执行（只读预研）默认关闭，由用户按来源显式开启。
- **Bot 工具**：`watch`、`unwatch`、`list_watches`、`read_event` 与 Main Bot 专用的 `manage_watcher`（仅限非隐私 Bot 的 `github`/`mail`/`folder`/`http` 探针）。
- **内部 Blackboard 协同**：群任务板（`group_task`）状态变更同步发出 `internal:group_task:<roomId>` 内部事件，供订阅的成员接力。

### 4. Watchdog 看门狗与界面

- **宿主看门狗（#781）**：零模型开销定时巡检僵死回合/后台任务（无输出、无工具进展、无活跃 job 且无待审批超过阈值）、孤儿订阅自动暂停、探针暂停与投递死信，全部汇入统一待处理视图。
- **设置 → 定时与触发**：复用原有定时任务入口，顶部通过分段控件分为「定时 / 探针与推送 / 订阅与时间线」三栏。
- **统一「待处理（Inbox）」**：侧栏顶部轻量入口带未处理计数，弹窗汇聚跨 Bot/群的审批、提问、请求与看门狗告警，支持一键跳转、恢复探针/订阅或重放死信。

## 不做什么

- 不开放公网 Webhook 端口，不内置内网穿透。
- 不新增全局 Router Bot，不改 DeepSeek Harness 本体代码。
- 不允许任何 Bot 通过工具创建或修改本地命令探针，不允许触碰隐私 Bot 的探针与事件。
- 不默认开启自动推测执行，不悄悄丢弃超限或投递失败的事件。

## 已知限制

- 轮询类探针并非毫秒级推送（最小间隔 15 秒）；电脑休眠或关闭 DS Bot 期间不运行，恢复后按游标补收新事件。
- 后台任务直通依赖 Bot 后台任务（#783）合并后完整生效；未开启后台任务时订阅照常直通 Bot 前台或群聊。
