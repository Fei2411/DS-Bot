## 为什么

新用户从下载安装包到收到第一条有效回复之间，常见流失点集中在三处：下载与系统安全拦截提示不清晰、首次启动先弹抽象目录对话框、以及缺模型/缺 Key 时报错生硬无引导。上手流程围绕「默认无打扰、仅在必要时用页内卡片提问、失败提供可操作出路」展开。

## 已定的行为

### 1. 下载与发布资产

- GitHub Release 由发版工作流自动生成置顶的「Download / 下载」表、`SHA256SUMS.txt` 校验和以及不带版本号的稳定文件名副本（如 `DS-Bot-win-x64.exe`）；全部资产上传完成后才自动标记为 Latest。
- README 中英版说明系统未签名提示的放行步骤（Windows「更多信息 → 仍要运行」、macOS「系统设置 → 隐私与安全性 → 仍要打开」）。

### 2. 安装与卸载（Windows）

- NSIS 安装向导（`oneClick: false`）：仅安装给当前用户、不请求管理员权限，默认目录 `%LOCALAPPDATA%\Programs\DS Bot`，支持向导中修改程序目录。
- 卸载仅移除程序文件，保留用户的数据位置、总工作区与应用自身壳数据，防止误删团队与对话。

### 3. 首次启动与位置规则

- 启动立即显示固定尺寸的[启动窗口](2026-10-26-start-window.md)，不弹系统文件夹对话框。
- 默认直接采用 `~/.ds-bot`（数据位置）与 `~/DS Bot`（总工作区），启动就绪并完成导入选择后记入壳数据的 `locations.json`。
- **空间不足或默认目录不可写时**：启动窗口底部显示位置行（含「换个位置…」按钮）或推荐盘卡片（Windows 上筛选剩余空间充足的非可移动磁盘）；用户也可点选自定义目录，经应用自建文件夹选择器定根（空目录/新目录直接使用，非空目录在其下建立 `DS Bot`，数据与总工作区分别放在 `<根>/data` 与 `<根>/workspace`）。
- 拒绝无写权限、OneDrive 同步目录、用户原 `~/.dsh` 数据目录、程序安装目录及互相包含的路径，并直接在卡片中说明原因。
- 首次启动未完成前退出不写入 `locations.json`，下次启动重新走完整流程。

### 4. 导入已有 DSH 团队

- 若检测到 `~/.dsh`（或 `DSH_HOME`）存在旧 Bot 团队而新数据目录为空，启动窗口在数据阶段完成后弹出导入卡片，可选择「复制过来」或「先不复制」（原 `~/.dsh` 始终只读、绝不修改）。
- 复制前检查旧团队是否被运行中的 DSH 锁占用（同机存活进程且 `state.lock` 在 60 秒内刷新）；并在临时副本（`.import-check-*`）上用锁定版 DSH 预读对话，确认没有更新版本写入的不兼容记录。
- 复制过程在独立暂存目录（`.import-*`）中完成并切入新数据位置，支持跳过工作文件；若中途取消或失败会清理暂存、保留原状。导入后各 Bot 和群在下一回合自动换段至新工作文件夹。

### 5. 模型连接

- 桌面应用通过 `app/src/app-patch.mjs` 关闭 DSH Web 的自动凭据引导（`credentialOnboarding: false`），避免与 DS Bot 引导重复。
- Main Bot 尚无可用模型时，聊天内显示模型配置卡片（`model-menu.js`）：可直接填写 API Key、使用宿主账号登录入口（授权页交由系统浏览器完成），或进入 **设置 → 模型 → 提供方** 配置任意服务商。

### 6. 改位置、恢复与更新

- 后续可在 **设置 → 通用 → 位置** 分别修改总工作区（立即生效，相关 Bot 下一回合换段）与数据位置（停引擎 → 暂存复制 → 原子切换并重启，旧目录原样保留供用户确认后自删）。
- 启动失败或超时（180 秒）直接在启动窗口切换为恢复卡，提供重试、复制脱敏详细信息、保存日志，以及在检测到新版本时直接提供更新入口。

## 不做什么

- 不修改或写入用户原有 `~/.dsh` 目录。
- 不自动读取剪贴板或静默搬运未授权凭据，不使用应用内非隔离登录子窗口。
- 卸载时不自动清空用户团队数据。

## 已知限制

- Windows / macOS 安装包目前未购买商业开发者证书签名，首次打开仍会触发系统安全提示。
- DSH 网页版的「预览版说明」首屏暂无公开关闭开关（见 [DSH 让步总账](2026-10-13-dsh-concessions.md) C17）。
