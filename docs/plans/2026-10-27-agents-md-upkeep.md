# 从项目工作中提出 AGENTS.md 更新

- 日期：2026-10-27 定行为
- 代码：`ds-bot/src/host/learning.js`、`src/client/learning-card.js`

## 为什么

用户对项目的长期要求、反复纠正和检查步骤适合保存在项目的 `AGENTS.md`，让之后在该文件夹工作的 Bot 都能读取。文件应保持简短、准确；Bot 只能提出有工作证据支持的修改，不能自行写入。

## 已定的行为

- 复用现有学习调度和待审工作记录。一个文件夹每轮最多审阅一次，并汇总其中所有 Bot 的工作。
- 只审阅 `workFolder` 检查通过，且包含 `.git` 或 `AGENTS.md` 的文件夹。不存在的 `AGENTS.md` 只可在含 `.git` 的文件夹中新建。
- 默认不修改。候选规则必须适用于大多数后续任务、有证据支持、不显而易见、长期有效，且不能与文件中已有规则重复。
- 提案只包含 1–3 项精确的整行添加、替换或删除。检查密钥、日期、版本和任务编号；过大的文件、无效或没有实际变化的结果不提出。
- 提案显示在相关 Bot 的对话卡片中，包含文件夹、逐项差异和理由。只有用户批准后才写入。
- 批准前重新检查文件是否仍与提案时相同；匹配时在同一文件夹写临时文件并原子替换。文件变化时保留提案，用户可以拒绝。
- 拒绝的修改按文件夹记录，供之后的审阅参考。`agentsMd: false` 只关闭项目文件审阅，不关闭技能学习。

## 不做什么

- 不自动写入或替换项目文件。
- 不为普通任务创建定时器，不审阅没有项目标记的文件夹，不将单次任务进展写入 `AGENTS.md`。

## 已知限制

- Bot 是否提出更新取决于模型能否从有限的工作记录中识别出持久、可复用的规则；不确定时应不提出。
- 只处理符合大小限制且能读取的 `AGENTS.md`。
